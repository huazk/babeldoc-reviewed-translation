# 网络层课件：为何这次效果更好

验证材料：一份英文计算机网络课件，81 页。记录于 2026-10-12。本仓库只记录处理方法和观察结果，不附原始课件或私人对话。

## 两次实际流程

| 环节 | 对照对话 | 本次成功做法 |
| --- | --- | --- |
| 软件 | PDFMathTranslate/pdf2zh 1.9.11 | BabelDOC 0.6.4 Python API |
| 译文来源 | Bing 免费翻译 | 当前助手生成并校订，写入本地映射 |
| 图内英文 | 部分作为原图保留 | RapidOCR 定位，再结合图像复核、翻译、回填 |
| 排版修复 | 三份 261 页中修复发现的 8 页问题 | 对本份 81 页全量渲染审查，并多轮局部修版 |
| 交付 | 三份中文、双语和实例册 | 本份 81 页中文、162 页逐页对照 |

对照方案也做过检查和修复，不能说它完全没有质检。

本次处理 640 个唯一翻译片段，回填记录缺失 0；其中 548 项变化，其他包含公式、缩写和数据。另应用 326 条图内 OCR 文字翻译（包含重复表头，不代表 326 张图）。零缺失只覆盖提取到的片段，并不证明 PDF 所有可见英文都已识别。

## 可观察差异

- 第 4 页：新译文将 forwarding 解释为“将分组从路由器的输入端口送到合适的输出端口”，类比使用“通过某一个立交路口”，术语和教学语境更统一。
- 第 12 页：补译图中的虚电路号、接口编号和转发表表头；保留原数值、图结构。
- 第 50、53 页：补译图内表头及“好消息传得快/坏消息传得慢”；将正文“数到无穷/无限计数”等不同译法统一为“计数到无穷”。
- 修复过条目合并、正文旧字残留、标题遮住表头，以及 BGP 路径公式被修补矩形影响的问题。说明即便采用 BabelDOC，直接输出仍需检查。

## 解释边界

本次同时更换了排版引擎、译文来源、OCR 范围和修版投入，无法定量隔离每项收益。可以判断完整流程改善了最终成果，不能断言 BabelDOC 原始输出必然优于任何 PDFMathTranslate 输出。

BabelDOC 本身是开源项目；沉浸式翻译是其在线使用入口之一，Python API 可在本机运行。新版 PDFMathTranslate-next 也使用 BabelDOC，因此两者不是永远对立的技术路线。

参考：[BabelDOC](https://github.com/funstory-ai/BabelDOC)、[PDFMathTranslate-next](https://github.com/PDFMathTranslate/PDFMathTranslate-next)。这两项是动态项目，比较当前版本时重新核实。

## 兼容性经验

曾遇到 sklearn 1.9.1 DLL 被 Windows 应用控制阻止，改用独立目录内的兼容版 1.7.2 后运行成功。不要关闭安全策略，也不要把该版本降级当作所有环境的必选操作。

后续三页复现测试再次确认：仅运行 BabelDOC 的文本回填不会翻译嵌入图片内的英文；OCR 补译和局部修版是独立环节。
